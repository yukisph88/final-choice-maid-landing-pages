# CLAUDE.md – final-choice-maid-landing-pages

Two identical single-page maid landing pages for Agensi Pekerjaan Final Choice Sdn. Bhd.: `/sales-1/` (Izzaty) and `/sales-2/` (Bella). Static HTML/CSS/JS generated by `build.mjs` (Node 22, no dependencies). Hosted on GitHub Pages: https://yukisph88.github.io/final-choice-maid-landing-pages/sales-1/ and `/sales-2/`.

## Rules (from APFC organisation instructions)
- Never invent company facts, prices, policies, names or testimonials. Unverified facts stay flagged.
- Never commit passports, NRIC, biodata PDFs, credentials, candidate contact details or videos. `.gitignore` blocks `*.pdf`, `private/`, `.env`.
- Never edit the existing Maid website repo (`yukisph88/final-choice-maid-agency`) or other APFC sites from here.
- Ask the owner before deploying, deleting, or changing release checks. Do not bypass or weaken release gates; do not mark anything `verified`/`confirmed` unless there is written evidence.
- No package prices anywhere (management decision). No ages shown (not approved).

## Architecture
- `build.mjs` renders both pages from one template using `configs/sales-1.json` and `configs/sales-2.json`. Only consultant name, WhatsApp number, display phone and campaign ID differ.
- Content: `content/company.json`, `content/packages.json` (no prices), `content/maids.json` (public, consent-verified maids only).
- Text: every `tx('Malay','English')` in `build.mjs`. Default language Bahasa Melayu; EN via the switch or `?lang=en`.
- WhatsApp messages: `src/messages.mjs` (`Hi {name}, …`, plus `(Ref: campaign[/utm_source])`).
- Styles `src/styles.css`, runtime `src/app.js` (inlined into each page). Assets in `assets/` use relative paths so the pages work under `/final-choice-maid-landing-pages/`.
- `private/` (gitignored, not in the repo): `maids.pending.json` + photos for candidates without confirmed consent (currently one candidate).

## Commands
```
node build.mjs                 # preview build (all content incl. unconfirmed 15+ claim) -> dist/
node build.mjs --with-pending  # preview incl. private pending maids (local only)
node build.mjs --release       # PUBLIC build; this is what CI deploys
node scripts/serve.mjs         # http://localhost:4173/sales-1/ and /sales-2/
node scripts/verify.mjs        # full QA + screenshots (needs: cd tools && npm i; Google Chrome)
PAGES_PATH=1 node scripts/verify.mjs   # same, served under /final-choice-maid-landing-pages/
node scripts/shoot-maid-cards.mjs      # screenshots of the maid cards
```
PowerShell: `$env:PAGES_PATH=1; node scripts/verify.mjs`.

## Release gates (all still in force)
1. **Maid consent:** the release build fails if any maid in `content/maids.json` has `consent.verified` not true. A maid without confirmed consent must live only in `private/`.
2. **Experience claim:** `content/company.json` → `experience.confirmed` is `false`, so the public build uses the non-numeric statement. Do not set it to `true` without management's verification against company records (see `docs/experience-claim-sources.md`).
3. **Numbers:** `placeholderNumber` must be false; the build blocks the known-wrong number `601433131112`.
4. `--with-pending` can never be combined with `--release`.
